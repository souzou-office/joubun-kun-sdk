# 条の系譜と判例の紐付けの付け直し（2026-10-15）

## 何のためか

判例の条文への紐付け（R2 `hanrei_v1/links/`）は、判決文の参照法条の条番号を、**今の**法令の同じ番号の条にそのまま付けている。判決のときの条文が今と違うと、別の中身の条に出たり（今の民訴法89条「和解の試み」に旧民訴法89条「訴訟費用の負担」を引く判例が3,223件）、どの条にも出なかったり（旧商法269条＝今の会社法361条）する。

これを直すために、**条の系譜**（規定ごとに、いつ・どの改正法で・番号の変更／削除／追加／書き換えが起きたか）を作り、「判決が使った版の第N条は、今の何条か」を引けるようにする。

## 材料と出典

| 材料 | 中身 | 使い方 |
|---|---|---|
| 名古屋大学「法令XMLデータ」（佐野智也・外山勝彦・増田知子、CC BY 4.0、https://doi.org/10.18999/2014084） | 1886〜2017年に公布された法律・勅令の XML（13,730本の法律）。一部改正法の改め文が構造つき（AmendProvisionSentence・NewProvision） | 原始の条文に改め文を順に当てる |
| 国立国会図書館「日本法令索引」 | 法令ごとの改正の履歴（どの改正法の何条で改正されたか・公布日） | 当てる改正法の一覧 |
| e-Gov 法令API v2 | 改正履歴（2012〜2016年以降の分・段ごとの施行日）と、時点ごとの版の XML（`law_file/xml/{law_revision_id}`。`asof=` は 2017-04-01 より前を返さない） | 答え合わせと、2018年以降のつなぎ |

**出典の表示**: 条文ページの出典の 1 行（`worker/lawpages.js` の `cx-src`）に、判例の紐付けのうち条番号が変わったものは名古屋大学「法令XMLデータ」（佐野智也・外山勝彦・増田知子、CC BY 4.0）の改正の経過に基づき今の条に付け直している、と書いた（CC BY 4.0 の表示。消さない）。MCP（`worker/mcp.js`）は判例の逆引き（links）を返さないので、今は足していない。MCP や画面で付け直した紐付けを出すときは、その出典の行にも足す。

## 作り方（`scripts/lineage/`）

1. **原始の条文**（名古屋大学の XML）から始め、日本法令索引の改正の履歴にある改正法を**公布の順**に当てる（改め文は、先に公布された改正を当てた後の文を前提に書かれるので、施行日の順ではずれる）。出来事の日付には施行日を置く。
2. **改め文のうち条の単位の指示だけを規則で読む**: 「第X条を次のように改める」（書き換え）、「…を削る」「第X条を削除す」（削除・削除の印）、「第X条を第Y条とし」（番号の変更・入れ替えは同じ改正法の間だけ脇に置く）、「第X条から第Y条までを第A条から第B条までとし」「以下…順次…繰下グ」（範囲の付け替え）、「…の次に次の…条を加える」（追加）、編章節ごとの書き換え・削除。文言の改正（「…」を「…」に改める）は同じ規定として扱い、本文にも当てる。目次・別表・附則の文は本則に当てない。
3. **e-Gov の一番古い版と答え合わせ**する（法令により2012〜2017年）。食い違った条は、名古屋大学のデータの書き誤りなど規則では直せないものとして e-Gov に合わせ、出来事に「e-Gov に合わせた」と残す。
4. **それより後は e-Gov の版を施行日の順に比べてつなぐ**（2018年以降の改正法の改め文は e-Gov から取れない）。同じ番号で本文が大きく変わった条・消えた条・増えた条を、本文の近さで突き合わせて番号の付け替えを見つける。
5. **条を丸ごと書き換えた所だけ、新旧の本文を Jev で「同じ事柄を定めた規定か」判定**する（`judge_rewrites.py`）。新しい条ごとに一番確からしい旧条だけを引き継ぎ元にする（並びの条を Jev が「同じ事柄」と言っても分かれたことにしない）。強く同じ（0.8以上）とされた旧条は統合として拾う。
6. **法令ごと作り直したもの・ほかの法令に移った規定**（`relink.py`）: 旧法も同じ仕組みで最後の版まで組み立て、受け皿の法令の制定時の条文から本文の近い順に8条を候補にして Jev で判定する。0.5以上で一番の受け皿と、2 つ目以降は 0.85 以上かつ一番との差が 0.1 以内の受け皿（分かれた場合）を残す（旧民訴法89条 → 61条 0.98・64条 0.83 の 64 条のような「関連するだけの条」に判例が何千件も並ぶのを避ける）。
7. **付け直しの表**（`tables.py`）: 系譜と Jev の判定と受け皿から、法令ごとに「その期間の第 N 条 → 今のどの条か」を期間で持つ表を作る（R2 `lineage_v1/tables/{法令ID}.json`）。判例ごとの付け直し（下の「判決が使った版の決め方」）はこの表を引くだけで、Jev も系譜の計算も要らない（`lib/currefs.cjs`。全件の作り直しと判例の週次で共用）。

### 改め文と施行日の読み方で足したもの（2026-10-15）

- 施行日のただし書が「第一条中所得税法第百五十一条の二の次に四条を加える改正規定」のように**一部だけ**を指すときは、その条から始まる改め文だけをその日にする（それまでは法令の改正全体をその日にずらしていて、所得税法の 151条の3〜6 が 2019 年まで出てこなかった）。「第一条（刑事訴訟法第九十条…の改正規定に限る。）」も同じ。「第一条（前号に掲げる改正規定を除く。）」は条の全体。
- ただし書の「次に掲げる規定　平成二十九年十月一日　イ　…　ロ　…」（イロハの入れ子）を読む。
- ただし書の日が「政令で定める日」なら、e-Gov の改正履歴の段の施行日を順に当てる（平成28年の刑事訴訟法の改正。本体の日＝最後の段は除く）。
- e-Gov は同じ日の版の一部を**条が 0 本の殻**で返す（地方税法）。答え合わせにもつなぎにも使わない（当てると全部の条が消えて新しい規定になる）。取れない版（404）も飛ばして記録する。
- 編章ごとの書き換えの範囲を読み違えて「同じ番号の新しい条に置き換えられた（指示なし）」で終わった旧条も、新しい条と組にして Jev の判定に回す（平成7年の刑法の現代語化で 35 条などが別の規定になり、判例が外れていた）。
- 議員立法の法令 ID（`325AC1000000100` 公職選挙法・`326AC0100000219` 土地収用法）は下 7 桁が番号。

## 条文ページに載せる条件（2026-10-16・オーナーと決めた方針）

- 基準は条文同士が似ているかではなく、**「旧法下・改正前の判例が示した判断・論理が、今の条の解釈にも通用するか」**。作り直しのときに確かなものだけ条文ページ（hanrei_v2/links）に載せ、確かでないものは載せない（検索のときに AI ゲートが質問の論点で判断し、使うなら「旧法下の判例」と明示する形は別途）。畳む枠（「判決当時は別の規定」）も作らない。
- 判定は `lib/currefs.cjs` の `decideShow`（全件の作り直しと判例の週次で共用）。currefs の各引用に `show`（載せた先 `[{ lawId, art, by: 'lineage'|'jev'|'opus', s?, reason? }]`）か `hide`（載せない理由）を持たせる。

| 引用の付け直し（how） | 載せるか |
|---|---|

## 判決が使った版の決め方

1. 判決文に「（…法律第N号による改正前のもの）」があれば、その改正法の施行日の前日の版（`03_parse.cjs` が lawRefs の `before` に残す。定義した略称「旧商法」の引用にも付ける）。
2. 無ければ判決日の版。刑事は行為時の法を当てることが多いが、判決文から行為の日を機械的に取るのは難しいので、まず 1. と 3. で拾う。
3. 判決日にその条が無ければ、今の法令ができる前の判決は旧法（受け皿で付け直す）、そうでなければ直前にその条があった日の版（経過措置で旧法を当てた・旧い番号のまま引いた）。

## 施行日

- 改正法の附則の最初の条から読む: 公布の日／日付／公布の日から起算して N 日（月・年）を経過した日／日本国憲法施行の日。ただし書の各号で別の日にした規定のうち、その法令を直した部分（「第二十七条の規定」「…の改正規定」）はその日。
- e-Gov の改正履歴に段ごとの施行日があれば（2012〜2016年以降の分）、そちらを正にする。
- **1947〜2016年の「政令で定める日」は、施行期日の政令が e-Gov にも名古屋大学のデータにも無い**（e-Gov の現行法令にも残っていない）。公布日〜附則に書いてある最大の期間の幅で持ち、出来事の日付には公布日を仮に置く。この幅の中の判決で、その条の番号や中身が変わる改正のときだけ版があいまいになる。
- 分かっている日での確かめ: 昭和22年法律第222号（1948-01-01）・平成7年法律第91号（1995-06-01）は附則から正しく読める。平成16年法律第147号・平成29年法律第44号は政令で定める日（幅）、平成8年法律第110号・平成17年法律第87号は「（ほかの法律）の施行の日から施行する」で、日付はデータに無い。

## 政令・省令

名古屋大学のデータは法律と勅令だけで、1947年以降の政令・省令は無い。**政令・勅令（判例が引く 223 本）は e-Gov の一番古い版（多くは 2017-04-01）を出発点にして、その後の版を施行日の順につなぐ**（`build.py` の `build_egov_only`。法律と同じ年・番号の政令を名古屋大学のデータと取り違えないよう、法令 ID が AC でないものはこちら）。それより前の判決の引用は系譜で引けない（改め文も時点ごとの版も無料の機械可読な形では無い）ので、今の同じ番号の条に付けたまま（how: nolineage）にし、日本法令索引の改正の履歴（公布日）から「この判決の後、この法令は○回改正されています（条までは確認できません）」の注記（ord）を付ける。省令（法令 ID が M…）は今は対象外（系譜なし・注記なし）。

1. 今の法令の公布の年より前の判決が同じ名前で引いている法令を数える（5 件以上）。
2. 旧法 = 今の法令の制定時の附則の「○○法（昭和二十二年法律第二十七号）は、廃止する」、無ければ日本法令索引で同じ題名の前の法律（続きのページまで見る）。
3. 旧法が終わった日 = 今の法令の施行日の前日（附則から）。受け皿 = 今の法令＋旧法の改正の履歴に出てくる、旧法が終わった前後 2 年に施行された題名の近い新しい法律。
4. 判決文で旧法を指す名前「旧○○法」。

2026-10-15 の結果: 26 組（旧教育基本法・旧会社更生法・旧所得税法（昭和22年）・旧非訟事件手続法・旧関税法・旧法人税法・旧都市計画法・旧酒税法・旧国税徴収法・旧銀行法・旧統計法・旧商標法・旧特許法・旧著作権法 など）。拾えなかったもの: 会社法（前は商法の会社の規定＝手で書いた組）・信託法（旧信託法は廃止ではなく題名が変わった）・保険法（前は商法の保険の規定）・銀行法以外のいくつか（`relink_auto.json` の skipped）。

## 判例の週次・月に 1 回の作り直し

- **判例の週次**（`scripts/hanrei/weekly/run.cjs`）: `hanrei_v2/index.json` があるときだけ、新しい判例の引用を付け直しの表（R2 `lineage_v1/tables/`）で引き、`hanrei_v2` の currefs・links・index にも足す（hanrei_v1 は今までどおり）。条文ページに載せるかは上の `decideShow`（`lineage_v1/policy/old_to_current.json` が読めなければ止める）。新しい判例の lawRefs は `03_parse.cjs` が before を持つ。表が読めなければ止める。退避と戻しは今の週次の仕組みのまま（manifest のファイルに hanrei_v2 も入る）。
- **月に 1 回の作り直し**（`.github/workflows/update_lineage.yml`・毎月 2 日 09:13 JST）: R2 の `lineage_v1/` を取り（`relink_hanrei.cjs pull`）、今の法令の系譜に e-Gov の新しい版を足し（`monthly.py`）、新しい書き換えを Jev で判定し（本番の Worker・1 回 2,000 組まで）、表を作り直し、判例の全件を R2 から読んで付け直し、**中身の変わったファイルだけ**退避してから書く（`relink_hanrei.cjs upload --changed-only`。退避は `update_state/hanrei_v2_backup/{run}/`）。付け直した引用の数が 5% を超えて変わった・判例の件数が R2 と違う（週次が間に入った）・判例の週次の作業中の印がある、のどれかなら書かずに止めて Issue（ラベル lineage-update）。判例の週次と同じ concurrency で同時に書かない。R2 に `lineage_v1/tables/index.json` が無い月は何もしない。
- 旧法と、名古屋大学のデータからの組み立て（`build.py`）は PC だけ（`LINEAGE_DATA` に材料がある PC）。系譜の対象の法令を足すときは PC で `build.py` → `judge_rewrites.py` → `tables.py` → `relink_hanrei.cjs build --cases-r2` → `upload`。
