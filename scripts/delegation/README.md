# 委任先（政省令）逆引き紐付けパイプライン

法令本文の「政令で定める」等の委任表現に、子法令（施行令・施行規則等）の受け皿条文を
**ルールベース（正規表現＋refs逆引き）** で紐付ける。AIは検査のみに使い、紐付け本体には使わない。

## パイプライン

| スクリプト | 役割 | 実行 |
|---|---|---|
| `00_index_refs.cjs` | refs_v2.json (506MB) をソース別 + target別逆引きに分割 | `node --max-old-space-size=14000 00_index_refs.cjs`（1回だけ） |
| `01_extract_delegations.cjs` | 親法令から委任表現を列挙 | `node 01_... <law_id>...` |
| `02_link_by_reverse.cjs` | 逆引き＋受け皿パターンで候補紐付け（本体） | `node 02_... <law_id>...` |
| `03_build_eval_set.cjs` | AI検査用データセット（precision/recall 2方向） | `node 03_... <law_id>...` |
| `04_ai_audit.cjs` | Claude API検査（Sonnet、失敗一般化のみOpus） | `node 04_ai_audit.cjs` |
| `05_report.cjs` | 集計レポート | `node 05_... <law_id>...` |
| `06_rollout_all.cjs` | 全法令展開（AIなし） | `node --max-old-space-size=8000 06_rollout_all.cjs` |

出力はすべて `{localDataRoot}/rebuild_output/delegations/`（ローカルのみ。R2には書かない。`{localDataRoot}` は `scripts/site_config.cjs` の localDataRoot）。

## 紐付けルールの要点

1. **varref合成**: 子法令の「法第N条」は varref（略称「法」）と条ポインタに分離されており、
   条ポインタは lawtext が子法令内部の条として解決失敗するとレコードごと消える。
   そのため **varref の直後を子条文テキストから直接パース** する（refsの隣接レコードに頼らない）。
2. **受け皿パターン（strong）**: 「〜に規定する／〜の規定により＋KINDで定める＋○○**は、**」。
   定義主語の「は」まで要求する（他法令からの言及と区別）。
3. **体系フィルタ**: 受け皿は親専属の下位法令のみ。専属性 = 短い汎用略称（法/令/規則等）での
   varref引用、または子法令題名が親法令名を含むこと。「法人税法」等のフルネーム略称varrefは
   専属の証拠にしない（地方税法施行令→法人税法などの越境を遮断）。
4. **文頭要件**: 受け皿の主語は文頭（または30字以内の前置き直後）。文中間・括弧内の引用はstrong不可。
5. **準用・読替え除外**: 「準用する」「読み替え」を含む文はstrong不可。
6. **種別整合**: 委任種別（政令/財務省令/内閣府令…）と子法令の法形式の両方が整合すること。
7. **名詞絞り込み**: 「〜で定める○○」の○○が親の後続語と決定的に一致（名詞全体 or 4文字以上、
   かつ唯一最良）した場合のみ1件に絞る。決定的でなければ複数のまま（＝multiple）。

## 列挙型の受け皿（2026-09-22 追加）

会社法施行規則 116 条のように、柱書が「次に掲げる規定に規定する法務省令で定めるべき事項は、当該各号に定める事項とする。」で、
各号が「法第四百四十条第一項」と引用だけを書く型。号の文には引用の後ろに何も無いので上の受け皿パターンに掛からず、
会社法 440 条 1 項・435 条 2 項など「法務省令で定める」がある条の半分以上が **none** に落ちていた
（ステージングで会社法 42 条を数えて発覚。逆参照には 116 条 → 440 条 1 項 のリンクが残っていたので、対応付けだけの取りこぼし）。

02 は、号の文が引用（＋括弧）だけのとき、同じ項の柱書（号の無い最初の文）を `ENUM_LEAD_PATTERNS` で判定する。
柱書が準用・読替えなら strong にしない。柱書の目的語（「事項」）は総称なので名詞照合は掛けない（号が規定を特定しているので位置で決まる）。

同日にあと 3 つ直した（いずれも会社法施行規則で実測。`check_link_patterns.cjs` に例がある）:

- **併記**「法第三百一条第一項又は第三百二条第一項の規定により…」（65 条）: 又は/及び/若しくは/並びに で続く条ポインタも同じ法令の引用として拾い、受け皿パターンは最後のポインタの後ろで見る。両方の条の委任に候補が付く
- **「後段」「前段」「本文」「ただし書」**（110 条「法第三百九十六条第一項後段の規定により」）を読み飛ばす。「…については、この条の定めるところによる」型は「…は、次款の定めるところによる」も受ける
- **名詞照合の総称**: 受け皿の目的語が「事項」「方法」「場合」「基準」、または親の後続語が「ところにより」（「法務省令で定めるところにより」）のときは名詞照合を掛けない。これまで「…で定めるところにより」の委任は受け皿の目的語と一致しようがなく、strong で拾えても weak に落ちていた

2026-09-22 の全法令の流し直し（`docs/relations/DELEGATION_ROLLOUT_20260922.md`。v1 → v2 で確定＋複数候補が 21.7% → 23.7%）で weak の分布を取り、大きい 2 型を直した:

- **準用先の受け皿**（2,000 件超）: 「第十二条（…）において読み替えて準用する法第四十九条第二項に規定する内閣府令で定める者は、…」。引用の前が「自法令の条 において（読み替えて）準用する」だけなら準用の文脈での受け皿として strong（候補に `via_junyo`）。直接の受け皿があればそちらだけで status を決め、準用先は候補の後ろに残す（07 も直接を先に出す）
  - 準用しているのが子法令の条（「第十二条において準用する法第…」）だけでなく、親法令の条（「法第十条第一項において準用する法第五十九条第二項に規定する…」＝親の中での準用を子が受ける型。分布で最多）も受ける（v3 の流し直しで前者だけでは 19 件しか掛からず発覚）
  - 候補に `weak_reasons`（no_pattern / cross_system / junyo / head / paren / noun）を残す。次に直す型を分布で見るため
- **専属フィルタの緩和**（1,000 件超）: 子法令の題名が親の題名を丸ごと含まなくても、末尾の「法」を除いた芯（3 文字以上。「金融商品取引法」→「金融商品取引」）を含めば専属とみなす

- **技術的読替え**（200 件超）: 親の「必要な技術的読替えは、政令で定める。」の受け皿は施行令の「法第N条第N項の規定による技術的読替えは、次の表のとおりとする。」。柱書だけで受け皿と分かるので strong（表の中身は要らない）

方針（2026-09-22・オーナー決定）: **機械で決められる受け皿だけ載せ、機械で決められるものは全部載せる。LLM の判定でデータを作らない**（判定がぶれる。LLM は監査だけ）。この方針で同日に足した 2 つ:

- **法令単位の受け皿**（`law_level`）: 条が決まらない（weak / none）政令・省令系の委任で、親法令に専属の施行令・施行規則（題名が `{親の題名}施行令` / `{親の題名}施行規則` で `src/lawIds.js` に 1 本ある。`lib.cjs` の `dedicatedChildLaw`）があれば、条ではなく **法令へのリンク**にする。「この法律の実施のため必要な事項は、政令で定める」のような包括委任がこれで拾える。子法令の種別（法令番号）が委任種別に合わないとき（「内閣府令で定める」に法務省令の施行規則）は付けない。confirmed / multiple は触らない。weak の候補はそのまま残す（07 も出す。条文ページは law_level のときは候補を出さず法令リンクだけ）
- **引用の前が略称・題名だけなら文頭扱い**: 受け皿の主語は文頭に来るという判定（head）で、「法第六条第一項の政令で定める事業年度は、」のポインタ側の ref（略称「法」の VarRef とは別の ref で、引用の前が「法」）と、「がん登録等の推進に関する法律（以下「法」という。）第二条第一項の政令で定める疾病は、」（題名で親を引く。前が題名と括弧だけ）が head で weak に落ちていた。前者は VarRef 側で確定していることが多いが、後者は VarRef が無く取りこぼし。引用の前（括弧を除く）が略称 1 語（法・同法・令・同令・規則など）か親法令の題名そのものなら文頭扱いにする。主語がある（「…について、法第八条第一項の…」）ものは従来どおり head
- **手続型の列挙型**: 会社法施行令 1 条「次に掲げる規定に規定する事項を電磁的方法により提供しようとする者は、法務省令で定めるところにより、あらかじめ、…承諾を得なければならない。」＋号「法第五十九条第四項」。政令が列挙した規定の手続そのものを書く型で、親側は「政令で定めるところにより」。柱書の「法務省令」は政令の中の再委任なので受け皿の種別とは読まない。親の後続語が「ところにより」の委任にだけ当てる（`tokoro`）。会社法 59・74・76・203・242・299・310・312 条などの「政令で定めるところにより」がこれで条単位になる（それまで法令単位に落ちていた）
- **告示**（`kokuji`）: 「厚生労働大臣が定める基準」など告示への委任は受け皿が法令 DB に無いので、none と分けて数えるだけ（表示しない）

通るので 5 分 1,200 件の共有上限を消費する。この配信物は 100 件前後で収まるが、見込みが `WRANGLER_MAX_REQUESTS`（既定 300）を超えると止まって api に誘導する）。

1. 上げた世代を `wrangler.staging.toml` の `DELEGATIONS_PREFIX` に書いた PR を main に入れ、**main を checkout してから** `wrangler deploy --config wrangler.staging.toml` で staging を確かめる
2. 良ければ `wrangler.toml` の `DELEGATIONS_PREFIX` とリポジトリの Variables `DELEGATIONS_PREFIX`（update_laws.yml の 05_diff が読む）を同じ値にした PR を main に入れ、**main を checkout してから** `wrangler deploy`

## status

| status | 意味 |
|---|---|
| `confirmed` | 強い受け皿パターン一致・種別一致・受け皿条が1つに特定 |
| `multiple` | 候補が複数条 or 原文の引用が包括的で構造上絞れない |
| `weak` | 引用はあるが受け皿パターン不一致（関連条文レベル） |
| `none` | 逆引き候補ゼロ |
| `law_level` | 条は決まらないが、親に専属の施行令・施行規則が 1 本ある → `law_level: {law_id, law_title}` に法令単位の受け皿（2026-09-22。旧 weak / none から） |
| `kokuji` | 告示への委任（受け皿は法令 DB に無い。表示しない。2026-09-22。旧 weak / none から） |

## 検証結果（2026-07-30、サンプル6法令・AI監査4ラウンド）

- **confirmed precision**: ラウンド3: 98.4%（wrong 0）、ラウンド4: 96.0%（wrong 0、ambiguous 4）。
  ambiguous 4件は手動検証ですべて正しい紐付けと確認（ジャッジの保守判定）。
  **confirmedのwrongは2ラウンド連続で0件**。
- **recall**: 96.3%（方向B、AI列挙との突き合わせ・実在検証後）。
  残りの「AIのみ検出」は「法令で定める」「定款で定める」等の非委任表現（AI過剰列挙）。
- 方向A全体: multiple/strong 55%、weak 25%（設計どおり低精度バケツに逃がしている）。

## 既知の限界

- 附則内の委任は紐付け対象外（refsのキーが本則と衝突するため）。`provision` で区別して出力。
- 読替え表・別表セル内からの引用は受け皿判定不可（構造上取得できない）。
- 同一項に同種委任が複数あり子の引用が包括的な場合、原文が特定していないので multiple になる（仕様）。
